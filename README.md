# Command de Cuisine

Clean production build for a professional kitchen.

## Storage
- PostgreSQL is the authoritative live multi-user data store.
- Google Drive stores customer-owned documents and JSON backups.
- The web service does not rely on SQLite or Render's ephemeral filesystem for operational data.

## First launch
1. Deploy the Blueprint in `render.yaml`.
2. Open the site.
3. The first-run screen asks for the business name and creates the first Admin account.
4. The Admin adds all other staff from **Team** and sets a temporary password for each person.
5. No demo users or default passwords are created.

## Google Drive
Create a Google service account, enable the Google Drive API, and share one Drive folder with the service-account email as an Editor. Set these Render environment variables:

- `GOOGLE_SERVICE_ACCOUNT_JSON` — the complete service-account JSON, stored as a Render secret.
- `GOOGLE_DRIVE_FOLDER_ID` — the ID of the shared root folder.

Command de Cuisine creates `Backups` and `Documents` subfolders inside that folder. It makes a daily JSON backup after the first successful state save of each UTC day, and an Admin can trigger a backup from Settings.

## Other environment variables
- `SESSION_SECRET` is generated by Render.
- `DATABASE_URL` is wired automatically to the Render Postgres database by the Blueprint.
- `OPENAI_API_KEY` is optional but required for AI features.

## Render sizing
The Blueprint uses the current lowest paid web-service compute plan (`0.5c-512mb`) and a small Render Postgres plan (`0.1c-256mb`).
